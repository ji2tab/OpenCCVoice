# **OpenCCVoice Guidance Controller**

取扱説明書 / コマンドリファレンス  
**バージョン: v1.73f-Unified-Safe**  
**最終更新日: 2026/02/13**  
対象ハード: Arduino Nano (ATmega328P / 5V)  
通信設定: 115200 bps / 8N1 / 改行なし(またはLF)

---

## ■ 概要

本機は DMR無線機のID送出を自動制御するコントローラです。  
PCとUSB接続し、シリアルモニタから各種コマンドで設定を変更できます。

全ての設定は EEPROM に自動保存され、電源断でも保持されます。  
**v1.73c から EEPROM にバージョン管理機能を搭載**し、スケッチ更新時の設定破損を防ぐ仕様になりました。  
**v1.73d では「周期IDの静寂ガード」機能（k####）** が追加され、通話中の割り込み問題を大幅に改善しました。  
**v1.73e では「送信直後ガード（postTxIgnore）」と「周期ID catch-up 対策」** により、実運用上の誤発火・連続発火を根治しました。  
**v1.73f では「`v`（バージョン確認）」と「`Z`（ソフトウェアリセット）」コマンド** を追加し、運用・保守性を向上しました。

## ■ 本バージョン（v1.73f）の特徴

### 【v1.73f 追加コマンド】

**`v` コマンド：バージョン確認**

- スケッチバージョンと EEPROM_VER を表示
- 起動ログを見逃した後でもいつでも確認可能
- 出力例：`[VER] OpenCCVoice v1.73f (EEPROM_VER=4)`

**`Z` コマンド：ソフトウェアリセット**

- ウォッチドッグタイマー（WDT, 15ms）で MCU を再起動
- EEPROM は変更しない（設定は保持されたまま再起動）
- `F` と組み合わせることで完全クリーン起動が可能

| 操作 | EEPROM | MCU | 用途 |
|------|--------|-----|------|
| `F` のみ | 初期値で上書き | 動き続ける | 設定のみリセット |
| `Z` のみ | 変化なし | 再起動 | 設定保持のまま再起動 |
| `F` → `Z` | 初期値で上書き | 再起動 | 完全クリーン起動 |

### 【v1.73e から継承：送信直後ガード・catch-up 対策】

**送信直後ガード（postTxIgnore）**

- PTT OFF 直後、A0 残留BUSY・スケルチテール・瞬間的な BUSY 揺れによる
  **短発ID（001）や周期IDの誤発火を防止**
- BUSY が連続して `idleMin` ms 以上 OFF になった時点で自動解除
- `isSuppressedNow()` に統合されており、短発・周期ID の両方に適用

**周期ID catch-up 対策**

- 長時間 BUSY/抑止が続いた後の **周期ID 連続送信を防止**
- `nextPeriodicAt` を `while` で未来へ追い付かせ、`periodicDue` は最大1回のみ立てる設計

**A0 BUSY 観測の安定化**

- 抑止中であっても A0 の BUSY 状態（`a0Busy`）は継続して観測
- 抑止中は AUTO 判定用カウント（`a0_event_count`）のみ増加させない

### 【v1.73d から継承：周期ID 静寂ガード（Quiet Guard）】

- 周期ID（002/003）は、**BUSY が OFF になってから k#### ms 静寂継続**した場合のみ送出
- BUSY中 / 静寂不足 / 抑止期間中は **延期（periodicDue保持）**
- 新コマンド：`k####`（既定：2000ms、`k0` で無効）
- `q` で `QUIET(ms)=xxxx` を確認可能

### 【EEPROM バージョン管理（v1.73c〜、config.ver=4）】

- 起動時に EEPROM のレイアウト版を判定
- 古いバージョンを自動補完 / 移行（マイグレーション）
- `q` に **EEPROM_VER=4** と表示

> **注意**：`k0` を設定して再起動すると、`migrateOrInit()` の補完ロジックにより
> `periodQuietMs` が 2000ms にリセットされる場合があります。
> 再起動後は `q` で QUIET(ms) を確認し、必要なら再度 `k0` を実行してください。

## 2. コマンド詳細解説

**[m：モード設定]**  
m0 … D6（デジタルBUSY）  
m1 … A0（アナログ）  
m2 … AUTO（D6/A0 を観測し優位側へ自動固定）  
※ AUTO中は D6/A0 どちらの入力でも ID が出る

**[b：最大受信長]**  
b3900（3.9秒）までを短発として受付  
dur ≥ b#### は長話と判定し 10秒抑止（LONG_SUP）

**[n / i：最小受信長 / 直前アイドル]**  
n#### … dur < n#### はノイズ扱い  
i#### … 直前アイドル < i#### は短発無効化

**[s / t / r：抑止ガード]**  
s1 … 抑止 ON（長話/バースト検出）  
t1 … 自局送出後、r#### ms BUSY を無視  
r#### … 送信後無視時間

**[p：周期ID]**  
p##（分）で 002/003 を交互送出  
絶対時刻基準で等間隔

**[k：周期IDの静寂ガード（v1.73d〜）]**  
周期IDを出すための「BUSY OFF からの静寂期間（ms）」

- 例：k2000 → BUSY 終了後 2秒静かなら送出
- 例：k5000 → より強い割り込み防止

**[w：AUTO観測期間]**

**[d：DFPフェイルセーフ]**

d0 で無効化

**[g：TM BUSY極性]**  
g0 = LOW=busy  
g1 = HIGH=busy（既定）

**[x / r：停止と再開]**  
x … 全動作停止

**[F：初期値へ]**

**[h / 0〜3：ヘルプ・ログ]**

0〜3 … ログレベル（NONE/ERR/INF/DBG）

## 3. 設定値解説（目的・実態・調整指針）

### 【m：BUSYソース選択】

無線機のBUSY信号をどのピンで受けるかを選ぶ。

- `m0`（D6）：デジタル入力。無線機のBUSY出力を直接接続する場合。
- `m1`（A0）：アナログ入力。スケルチ電圧等をヒステリシス判定で検出する場合。
- `m2`（AUTO）：起動後 `w##` 分間、D6エッジ数とA0イベント数を比較し、反応の多い側へ自動固定。固定後はEEPROMへ保存され再起動後も維持される。

実態として、固定配線が済んでいる場合は `m0` か `m1` を明示的に指定しておくのが安全。`m2` は初期設置・配線確認時に便利。

---

### 【b / n：カーチャンク検出窓】

BUSYの継続時間がこの範囲に収まった場合を「短発（カーチャンク）」と判定し、トラック001（ID音声）を送出する。

```
dur < n####              → ノイズ扱い（無視）
n#### ≤ dur < b####      → 短発＝カーチャンク → ID送出
dur ≥ b####              → 長話 → 10秒抑止
```

- `n####`（既定500ms）：これより短い受信はノイズとみなし無視する。電波状況が悪い場合は大きくする。
- `b####`（既定3900ms）：これ以上の受信は長話とみなし、10秒間の抑止に入る。通常の通話が短い環境では小さくしてよい。

調整指針：カーチャンクが検出されない場合は `n` を小さく、長話中に誤って ID が出る場合は `b` を大きくする。

---

### 【i：postTxIgnore 解除待ち時間】

> **注意：名称（直前アイドル時間）と実態が v1.73 系でずれています。**

現行コードでの実際の用途は **`postTxIgnore` ガードの解除閾値**のみ。  
「BUSY が連続して `i####` ms 以上 OFF になったら、送信直後ガードを解除する」という判定に使われる。

- 既定 200ms：送信終了後、スケルチテールや残留BUSYが収まるまでの待ち時間。
- 値を大きくするほど、送信直後ガードが長く維持される（誤発火防止効果が増す）。
- A0残留BUSYが長く続く環境では `i500` 程度に増やすと効果的。

本来の設計意図（「直前のアイドル時間が短すぎる場合に短発IDを無効化する」フィルタ）は、現行の不応期（`REFRAC_MS`=3000ms固定）が代替しているため、`i####` の短発判定への直接の影響はない。

---

### 【s / t / r：抑止ガード】

- `s0/1`：抑止機能全体の ON/OFF。`s0` にすると長話・バースト抑止が無効になる。汎用プリセット `H` も `s0` を設定する。
- `t0/1`：自局ID送出後の送信後抑止の ON/OFF。`s1` が前提。
- `r####`：送信後抑止の時間（ms）。自局がID送出した直後、この時間内に来た BUSY を無視する。再び相手が送信してきても反応しないバッファ時間。

実態として `s1 / t1 / r3000` の組み合わせが標準的な運用。混信環境では `r5000` 程度に延ばすと誤発火が減る。

---

### 【p / k：周期ID】

- `p##`（分）：`##` 分ごとにトラック002/003を交互送出する。`p0` で停止。絶対時刻スケジューリングのため電源投入後から等間隔になる。
- `k####`（ms）：周期IDを送出する前に「BUSY がOFFになってから `k####` ms 以上の静寂」を要求する静寂ガード。これが満たされない場合は送出を延期し、次の機会を待つ。

実態として `k2000`（2秒）が既定。通話が頻繁な環境では `k5000` 程度に延ばすと「会話中に定時IDが割り込む」体感が大幅に減少する。`k0` で静寂ガード無効（ただし再起動後は2000msにリセットされる既知の挙動あり）。

---

### 【w：AUTO観測窓】

`m2`（AUTO）選択時に、D6/A0 のどちらを採用するかを判定する観測期間（分）。  
観測窓内のエッジ数・イベント数が多い側へ自動固定する。

- 既定30分：設置直後の30分間の実際の受信状況で自動判定する。
- 短縮したい場合は `w1`〜`w5` で試験可能。

---

### 【L / G / a：A0アナログ判定パラメータ】

A0 ピンのアナログ電圧（0〜1023）をヒステリシスで BUSY 判定する。

- `L###`（既定300）：この値を**下回ったとき**に BUSY 開始と判定（立ち上がり閾値）。
- `G###`（既定700）：この値を**上回ったとき**に BUSY 終了と判定（立ち下がり閾値）。
- `a####`（既定800ms）：BUSY 終了判定後も `a####` ms は BUSY 状態を保持する（スケルチテール対策）。

L と G の差がヒステリシス幅になる。ノイズが多い環境では L を小さく、G を大きくして幅を広げると安定する。

---

### 【d：DFPlayer フェイルセーフ】

DFPlayer が再生を開始したまま BUSY ピンが戻らない（張り付き）場合に、`d####` ms 経過で強制的に PTT OFF する安全機構。

- 既定20000ms（20秒）：音声ファイルの最大長より長めに設定するのが原則。
- `d0`：無効化（SDカードの状態に関係なく PTT が張り付く可能性があるため通常は非推奨）。

音声ファイルが長い場合は `d####` を再生時間＋余裕分に合わせて調整する。

---

### 【g：TM BUSY 極性】

無線機の BUSY 出力の論理を合わせる。配線変更なしに対応できる。

- `g0`：LOW=受信（アクティブLOW、受信中に LOW を出力する無線機）
- `g1`：HIGH=受信（アクティブHIGH、受信中に HIGH を出力する無線機）（既定）

極性を間違えると短発・長話の判定が完全に逆転するため、初期設定時に必ず `q` で `TM_BUSY_POL` を確認すること。

## 4. LED表示の意味

[D4]  … D6 BUSY受信時点灯（AUTO中はD12と交互点滅）  
[D12] … A0 検知時点灯（AUTO中はD4と交互点滅）  
[D13] … 抑止/短発窓/AUTO固定（高速点滅）表示  
[D2]  … DFPlayer BUSYミラー（反転：再生中=HIGH）

## 5. フェイルセーフ（DFPlayer BUSY異常）

DFPlayer BUSY が戻らない場合、**d#### ms 経過後に強制 PTT OFF**。

- 既定：d20000
- d0：無効（判定スキップ）

## 6. トラブルシューティング

**● IDが出ない**

- 停止中（x）→ r
- 長話（b3900超）→ 抑止
- D13 点灯中（抑止）では動作しない
- 送信直後の postTxIgnore ガード中（BUSY が落ち着くまで自動解除待ち）

**● ID が止まらない**

- t1 と r#### を増やす
- n#### / i#### を大きくする

**● 送信後に ID が誤発火する**

- v1.73e の postTxIgnore ガードが有効か確認（ログレベル 3 で `[POST-TX] cleared` を確認）
- BUSY が落ち着かない環境では i#### を大きくする

**● 周期IDが連続して送出された**

- v1.73e の catch-up 対策が有効か確認
- 長時間の BUSY 後にまとめて送出される旧挙動は本バージョンで修正済み

**● 音声が途中で切れる**

- d#### を延長（d20000 など）
- SDカード階層（/mp3/0001.mp3）を確認
- D7(BUSY) が途中 HIGH になっていないか

**● BUSY判定が逆**

- g0/g1 の設定確認
- D6 は INPUT_PULLUP 必須

**● k0 を設定したのに再起動後に k2000 に戻る**

- 既知の挙動。再起動後に `q` で確認し、必要なら再度 `k0` を実行

## 7. 配線メモ（v1.73f）

```
DFPlayer TX → D10（Arduino RX）
DFPlayer RX ← D11（Arduino TX）
DFPlayer BUSY（LOW=再生中）→ D7
D7ミラー（反転）→ D2
TM BUSY → D6（g0/g1 で極性指定）
PTT → D5（HIGH=送信）
LED → D4（D6） / D12（A0） / D13（抑止/AUTO）
テストSW → D3（INPUT_PULLUP）
```

## 8. v1.73f 仕様まとめ

**【v コマンド：バージョン確認】**

- `v` を入力するとスケッチバージョンと EEPROM_VER を表示
- 出力例：`[VER] OpenCCVoice v1.73f (EEPROM_VER=4)`
- 起動ログを見逃した後でもいつでも確認可能

**【Z コマンド：ソフトウェアリセット】**

- ウォッチドッグタイマー（WDT, 15ms）で MCU を再起動
- EEPROM は変更しない（設定を保持したまま再起動）
- `F` の後に `Z` を実行すると完全クリーン起動になる
- シリアル出力を確実に吐き出してから WDT 発火（delay 100ms 挿入）

**【送信直後ガード（postTxIgnore）】**（v1.73e 継承）

- PTT OFF 直後に `postTxIgnore = true` をセット
- BUSY が `idleMin` ms 連続 OFF になるまで、短発・周期ID を抑止扱いにする
- `isSuppressedNow()` に組み込まれており、既存の抑止ロジックと統一

**【周期ID catch-up 対策】**（v1.73e 継承）

- `nextPeriodicAt` の更新を `while` ループで実施
- 長時間延期後も `periodicDue` は最大1回のみ
- ログレベル DBG（3）で `[Periodic] due flag set (catch-up)` を確認可能

**【EEPROM バージョン（CONFIG_VERSION=4）】**

- v1.73f は EEPROM レイアウト変更なし（v1.73d/e と同一）
- v1.73d/e（ver=4）からの更新では自動移行不要、EEPROM をそのまま継続利用可能
- v1.73c 以前からの更新時は自動マイグレーションが実行される
