# OpenCCVoice Guidance Controller
# アップグレード手順 (〜v3.00)
# 最終更新日: 2026-05-07

本書は、OpenCCVoice を **v3.00** にアップグレードする際の  
重要な注意点・確認手順をまとめた技術者向けドキュメントです。

特に **v2.24f / v2.10 / v2.01 / v1.73 系** からの更新時にご確認ください。

--------------------------------------------------------------------

## 1. v3.00 の概要（v2.24f + v1.80i 統合刷新版）

v3.00 は、v1.80i の堅牢なロジック設計と v2.24f の高機能（DS3231 RTC /
AT24C32デュアルEEPROM / イベントログ）を統合した、完全リファクタ版です。

### 主な変更点

| 領域 | v2.24f | v3.00 |
|------|--------|-------|
| 抑止タイマー | 4種（busy/long/burst/postTx） | **1種（busySupUntil）** |
| PTT判定方式 | 相対時間（stateTimer） | **絶対時刻（pttPreEndAt等）** |
| 定周期ID | catch-up + periodicDue | **シンプルなスキップ** |
| ファイル構成 | 3ファイル（.ino + .h × 2） | **1ファイル（.inoのみ）** |
| EEPROM_VER | 6 | **7** |
| BUSY_MAX デフォルト | 3900ms | **1500ms** |
| TX_SUP デフォルト | 3000ms | **10000ms** |

### 廃止コマンド

| 旧コマンド | 廃止理由 |
|----------|---------|
| `s0/s1` | 抑止は常時有効に統一 |
| `t0/t1` | POST後抑止は常に有効に統一 |
| `i####` | 抑止に統合（postTxIgnore廃止） |
| `H` | プリセット機能廃止 |

→ 入力時は `[CMD] Obsolete command (廃止)` を表示。

## 2. EEPROM の扱い（v2.24f → v3.00）

### ● 原則：自動マイグレーションあり、手動操作不要

v3.00 は v6 EEPROM レイアウトを v7 に**自動変換**します。
スケッチ書き込み後、特別な操作（F や Z）は **不要**です。

### ● 起動時に出る想定ログ

#### v2.24f（ver=6）からの更新時:
```
[RTC] DS3231 found.
[EEPROM] Migrated from V6 (internal).
[EEPROM] Settings Loaded.
[START] OpenCCVoice v3.00
[CFG] EEPROM_VER=7 ...
```

#### 既に v3.00（ver=7）で書き込み済みの場合:
```
[RTC] DS3231 found.
[EEPROM] Settings Loaded.
[START] OpenCCVoice v3.00
[CFG] EEPROM_VER=7 ...
```

#### 初回書き込み or EEPROM破損時:
```
[EEPROM] Init defaults.
[START] OpenCCVoice v3.00
```

### ● マイグレーションで起こること

v6（v2.24f）→ v7（v3.00）の自動変換時：

| フィールド | 動作 |
|----------|------|
| `pttPreMs` | **新規追加 → 1000ms** |
| `pttPostMs` | **新規追加 → 1000ms** |
| `busyMax` | **3900の場合 → 1500に更新**、それ以外は維持 |
| `txSupMs` | **3000の場合 → 10000に更新**、それ以外は維持 |
| `suppressOn` | **削除（無視）** |
| `txAfSupOn` | **削除（無視）** |
| `idleMin` | **削除（無視）** |
| その他 | 値を維持 |
| `ver` | 6 → **7** |

### ● 起動後に必ず実行すべき確認

`V` でバージョン確認:
```
[VER] OpenCCVoice v3.00 (EEPROM_VER=7)
```

`q` で設定確認:
```
[CFG] EEPROM_VER=7 SRC=DIGITAL MIN=500 MAX=1500 PRE=1000 POST=1000 SUP=10000 ...
```

チェックポイント:
- ✅ `EEPROM_VER=7`（マイグレーション成功）
- ✅ `MAX=1500` （旧3900なら自動更新済み）
- ✅ `SUP=10000` （旧3000なら自動更新済み）
- ✅ `PRE=1000 POST=1000` （新規追加項目）

## 3. ファイル構成の変更

### v2.24f の構成（3ファイル）
```
CCVoice_2_24f/
  ├── CCVoice_2_24f.ino
  ├── ccvoice_log.h
  └── ccvoice_config.h
```

### v3.00 の構成（1ファイル）
```
CCVoice_3_0/
  └── CCVoice_3_0.ino    ← これだけ
```

### 変更理由
- **同期コスト低減**: 構造体変更時のヘッダ側修正漏れを防止
- **配布の簡便さ**: Arduino IDE で 1ファイル開くだけ
- **個人開発の規模に最適**: 600行程度なら統合が現実的

⚠️ **重要**: 古い `ccvoice_log.h` / `ccvoice_config.h` を **同フォルダに残さない**でください。
v3.00 の関数と二重定義になり、コンパイルエラーになります。

## 4. 動作仕様の変更

### ● 抑止ロジック（busySupUntil 一本化）

#### v2.24f
- `longSupUntil`：長話抑止（10秒）
- `burstSupUntil`：バースト抑止（10秒、10秒窓内に2回以上）
- `postTxIgnore`：送信直後ガード（idleMin 安定まで）
- `busySupUntil`：送信後抑止（TX_SUP_MS）

#### v3.00（一本化）
- `busySupUntil`：唯一の抑止タイマー
  - **起点A**: PTT POST終了時にセット
  - **起点B**: ②超え受信終了時にセット

### ● PTT制御（絶対時刻判定）

#### v2.24f（相対時間、危険）
```cpp
if (now - stateTimer >= PTT_PRE_MS) { ... }
```
※ `parseInt()` ブロッキング中に millis() が進むと判定がスキップされる可能性

#### v3.00（絶対時刻、安全）
```cpp
if ((long)(now - pttPreEndAt) >= 0) { ... }
```
※ ブロッキングが起きても確実に PRE/POST 時間が確保される

### ● 定周期ID（シンプルスキップ）

#### v2.24f
- `periodicDue` フラグで延期管理
- 抑止解除後に蓄積分が一気に発火する可能性

#### v3.00
- フラグなし、その場で判定
- 条件不成立時は破棄（延期しない）
- 連続送出を完全に防止

## 5. 「F（初期化）」は必要か？

### ● 原則：不要

v6 → v7 の自動マイグレーションが正常に機能するため、F は不要です。

### ● ただし以下の場合は F を推奨

- v2.20以前から一気に更新した
- 過去に手動でおかしな値を設定した覚えがある
- 今回を機にクリーンな状態で運用したい
- 起動ログで Migration が複数回出る等の異常が見られた

実行手順：
```
F           ← Factory Reset
q           ← 設定確認
T20260507120000   ← RTC再設定
```

## 6. v3.00 固有の注意点

### ● `j####` / `J####` コマンド（PRE/POST 可変化）

v2.24f では PTT_PRE_MS / PTT_POST_MS は固定（1000ms）でしたが、
v3.00 では可変化されました（EEPROM保存）。

```
j1500       ← PRE = 1500ms に変更
J800        ← POST = 800ms に変更
q           ← 確認
```

### ● 廃止コマンドの動作

```
s0          ← 旧コマンド入力
[CMD] Obsolete command (廃止)   ← 表示されるが何も起こらない
```

スクリプト等で旧コマンドを使っている場合は除去してください。

### ● バースト抑止の廃止

v2.24f まであった「10秒窓内に短発2回以上で抑止」のロジックは廃止されました。
カーチャンクが連続しても、各カーチャンクごとに ID が送出されます
（ただし起点A/Bの抑止は適用されます）。

### ● 送信直後ガード（postTxIgnore）の廃止

v1.73e で導入された「PTT OFF 後の安定待ち」ロジックは廃止されました。
代わりに busySupUntil（起点A）で 10秒間の抑止が掛かります。

実用上は v2.24f より厳しい抑止になります。
緩めたい場合は `r####` で抑止時間を短く調整してください。

### ● イベントログの BST（バースト抑止）

v3.00 では BST イベントは**発行されません**（バースト抑止廃止のため）。
ただし、過去の v2.x で記録された BST ログを表示する処理は残っています。
新規の BST 記録はゼロになります。

### ● k0 設定の注意

`k0`（静寂ガード無効）を設定して再起動した場合、
`migrateOrInit()` の補完ロジックにより `periodQuietMs` が 2000ms にリセットされる場合があります。
再起動後は `q` で QUIET(ms) を確認し、必要なら再度 `k0` を実行してください。

## 7. RTC / AT24C32 関連（v2.24f から継承）

DS3231 RTC と AT24C32 EEPROM の動作・コマンドは v2.24f と同じです。

| コマンド | 機能 |
|---------|------|
| `T20260507120000` | RTC時刻設定 |
| `u0` / `u1` | RTCアライン無効/有効 |
| `v` / `v0` | ログ表示/消去 |

詳細は `DS3231_CONNECTION_GUIDE.md` を参照。

## 8. アップグレード後のチェックリスト（v3.00）

```
1. CCVoice_3_0.ino を Arduino IDE で開く
2. 古いヘッダファイル（ccvoice_log.h / ccvoice_config.h）を
   同フォルダから【削除】する
3. スケッチを書き込む
4. シリアルモニタ（115200bps）で起動ログを確認
   - "Migrated from V6" が出れば自動移行成功
5. V を実行し "OpenCCVoice v3.00 (EEPROM_VER=7)" を確認
6. q を実行し以下を確認：
   - EEPROM_VER=7
   - MAX=1500（旧3900から更新済み）
   - SUP=10000（旧3000から更新済み）
   - PRE=1000 POST=1000（新規項目）
   - TM_BUSY極性（POL）が無線機と一致
7. RTC接続時：T で時刻設定 → q で時刻確認
8. 短発ID（001）が正常に動くか確認
9. 周期IDが通話中に割り込まないことを確認
10. v でログ表示 → "BOT ver=7" 等が記録されているか確認
11. Z コマンドで再起動 → 設定が保持されていることを確認
12. 必要なら r#### / k#### を運用に合わせて調整
```

## 9. よくある質問（FAQ）

**Q1. v2.24f → v3.00 は特別な操作が必要？**  
→ 通常は不要です。スケッチ書き込みのみで自動マイグレーションされます。
ただし、古いヘッダファイル（`ccvoice_log.h` / `ccvoice_config.h`）は
スケッチフォルダから**削除してください**。

**Q2. なぜヘッダファイルを統合したの？**  
→ 個人開発・中規模での同期コスト低減と、Arduino IDE での扱いやすさのためです。
v2.24f までは構造体変更時にヘッダ側の修正漏れが発生するリスクがありました。

**Q3. 旧設定（カスタム値）は残る？**  
→ 残ります。MAX と SUP のみ「旧デフォルト値の場合に新デフォルト値へ自動更新」されます。
それ以外の設定値（n / p / k / 等）はすべて維持されます。

**Q4. 抑止が強くなりすぎてID送出されない**  
→ v3.00 はデフォルト SUP=10000ms です。
v2.24f より長いため、運用に合わせて `r####` で短くしてください（例: `r5000`）。

**Q5. バースト抑止が無くなって連続発火が心配**  
→ 各カーチャンクごとに busySupUntil（10秒）が掛かるため、連続発火は実質防止されます。
それでも気になる場合は `r####` を長くしてください。

**Q6. PTT中に Z を実行したら？**  
→ WDT によるハードリセットのため PTT は即座に解放されます（v2.24f と同じ）。
意図せず実行しないよう注意してください。

**Q7. ログレベルを保存したい**  
→ ログレベル（l0〜l3）はEEPROMに保存されません。起動時は常に `l1=MIN` です。
これは意図的な仕様（誤操作で OFF のまま運用される事故防止）です。

**Q8. 古いV6設定に戻したい**  
→ 戻せません。v3.00 は片道マイグレーションです。
どうしても戻したい場合は v2.24f を再書き込みし、`F` で初期化してください。

**Q9. 周期IDが catch-up しなくて困る**  
→ v3.00 は意図的に catch-up を廃止しました（連続発火防止のため）。
正時アラインを使うと、通話中でも次の正時には確実に送出されます（条件不成立時のみスキップ）。
