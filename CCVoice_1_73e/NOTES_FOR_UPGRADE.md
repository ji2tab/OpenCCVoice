# OpenCCVoice Guidance Controller  
# アップグレード注意点（〜v1.73e）
# 最終更新日: 2026-02-13

本書は、OpenCCVoice を **v1.73e** にアップグレードする際の  
重要な注意点・確認手順をまとめた技術者向けドキュメントです。  
特に **v1.73d / v1.73c / v1.73b / v1.72 / v1.69 系** からの更新時にご確認ください。

--------------------------------------------------------------------

## 1. v1.73e の概要（機能変更なし・安定性向上のみ）

v1.73e は **機能追加なし、実運用安定性の向上のみ**を目的としたリリースです。  
EEPROM レイアウトは **v1.73d と同一（`config.ver = 4`）** のため、  
既存機の EEPROM を破壊せずそのままアップデートできます。

### v1.73e で修正された問題

| 問題 | 原因 | 対策 |
|------|------|------|
| 送信直後に短発ID・周期IDが誤発火 | A0 残留BUSY・スケルチテール | `postTxIgnore` ガード追加 |
| 周期IDが延期後に連続送出された | catch-up 時に複数回発火 | `while` による `nextPeriodicAt` 追い付き |
| 抑止中に A0 観測が停止し AUTO 判定がずれた | 抑止中の `a0Busy` 更新を止めていた | 抑止中も BUSY 観測を継続、カウントのみ停止 |

## 2. EEPROM の扱い（v1.73d → v1.73e）

### ● 原則：書き込み後の操作不要

v1.73e は EEPROM レイアウト変更なし。スケッチ書き込み直後に  
**「F（初期化）」を実行する必要はありません**。

### ● 起動時に出る想定ログ

```
[EEPROM] Settings Loaded.
[START] OpenCCVoice v1.73e Unified/Safe (+Catch-up fix +PostTx guard)
```

v1.73d（ver=4）からの更新では Version mismatch は出ません。  
v1.73c 以前（ver≤3）からの更新では自動マイグレーションが実行されます。

### ● 起動後に必ず実行すべき確認

`q` を入力：

```
[CFG] EEPROM_VER=4 SRC=D6 ... TM_BUSY_POL=HIGH=busy DFP_TIMEOUT(ms)=20000 QUIET(ms)=2000
```

チェックポイント：
- `EEPROM_VER=4`（正常）
- BUSY 極性が無線機仕様に一致（g0/g1）
- DFP_TIMEOUT が意図した値
- QUIET(ms) が意図した値（k0 設定後の再起動で 2000 に戻る場合あり）

## 3. v1.73c 以前からのアップグレード（EEPROM 自動移行）

### ● v1.73c 導入の EEPROM バージョン管理

v1.73c から `config.ver`（EEPROMレイアウト版）を管理しています。  
古いバージョンからのアップグレード時は、起動時に以下を自動実行します：

- `config.magic` 不一致 → 完全初期化（applyDefaults）
- `config.ver` 不一致 → 自動マイグレーション（新規項目を安全値で補完）

### ● 旧EEPROMからの自動補完値

| 項目名 | 役割 | 補完値 |
|--------|------|--------|
| `tmBusyActiveHigh` | BUSY 極性（D6） | 1（HIGH=busy） |
| `dfpTimeoutMs` | DFPフェイルセーフ時間 | 20000ms |
| `periodQuietMs` | 周期ID静寂条件 | 2000ms |
| `ver` | EEPROMレイアウト版 | 4 |

### ● v1.73c 以前からの起動時ログ例

```
[EEPROM] Version mismatch: stored=3 expected=4
[EEPROM] Migration/completion done -> updated version.
[EEPROM] Settings Loaded.
[START] OpenCCVoice v1.73e Unified/Safe (+Catch-up fix +PostTx guard)
```

## 4. 「F（初期化）」は必要か？

### ● 原則：不要

v1.73c 以降の自動移行が正常に機能するため、通常は F 不要です。

### ● ただし以下の場合は F を推奨

- v1.69 系以前から一気に更新した
- 過去に手動でおかしな値を設定した覚えがある
- 今回を機にクリーンな状態でやり直したい
- 起動ログに異常値補正が多数出た場合

実行手順：

```
F
q
```

## 5. v1.73e 固有の注意点

### ● postTxIgnore ガードの動作

PTT OFF 直後、`postTxIgnore = true` がセットされ、  
BUSY が `idleMin` ms 連続 OFF になるまで短発・周期ID が抑止されます。

この間にトリガーが来ても無視されるため、  
送信直後のスケルチテールによる誤発火が防止されます。

ログレベル DBG（3）で確認：

```
[POST-TX] cleared by idle-stable
```

### ● 周期ID catch-up の動作

長時間の BUSY や抑止が続いた後、解除時に周期IDが溜まっていても  
**最大1回分しか送出しません**。次の周期は `nextPeriodicAt` から再スケジュールされます。

ログレベル DBG（3）で確認：

```
[Periodic] due flag set (catch-up)
[EVT] Periodic ID (quiet ok)
```

### ● k0 再起動後のリセット（既知の挙動）

`k0`（静寂ガード無効）を設定して再起動した場合、  
`migrateOrInit()` の補完ロジックにより `periodQuietMs` が 2000ms にリセットされる場合があります。  
再起動後は `q` で QUIET(ms) を確認し、必要なら再度 `k0` を実行してください。

## 6. アップグレード後のチェックリスト（v1.73e）

```
1. スケッチを書き込む
2. 起動ログに "Settings Loaded." が出ることを確認
   （v1.73c以前からの更新は "Migration/completion done" も確認）
3. q を実行し、以下を確認：
   - EEPROM_VER=4
   - TM_BUSY_POL が無線機と一致
   - DFP_TIMEOUT(ms)=20000（または意図した値）
   - QUIET(ms) が意図した値
4. BUSY の極性を実機で確認（g0/g1）
5. 短発ID（001）が正常に動くか確認
6. 周期IDが通話中に割り込まないことを確認
7. 送信直後の誤発火がないことを確認
8. 必要なら k#### / i#### を調整
9. 必要なら F でクリーン初期化 → 再設定
```

## 7. よくある質問（FAQ）

**Q1. v1.73d → v1.73e は特別な操作は必要？**  
→ 原則なし。スケッチ書き込みのみで完了。EEPROM はそのまま引き継がれます。

**Q2. 旧設定は残る？**  
→ 残ります。新規項目のみ安全値で補完されます。

**Q3. 送信後に ID が出てしまう（誤発火）**  
→ v1.73e の postTxIgnore ガードが機能しているか、  
　ログレベル 3 で `[POST-TX]` ログを確認してください。  
　また `i####`（idleMin）を大きくすることでガード解除までの時間を延ばせます。

**Q4. 周期IDが連続して出た**  
→ v1.73e で修正済みです。スケッチのバージョンを確認してください。

**Q5. 周期IDがまだ割り込む感じがする**  
→ `k####` が短い可能性。`k3000〜k5000` などへ調整してください。

**Q6. BUSY判定が逆っぽい**  
→ `g0（LOW=busy）` / `g1（HIGH=busy）` を確認。  
　`q` で TM_BUSY_POL を確認可能。

**Q7. k0 を設定したのに再起動後に k2000 に戻る**  
→ 既知の挙動です。再起動後に `q` で確認し、必要なら再度 `k0` を実行してください。
