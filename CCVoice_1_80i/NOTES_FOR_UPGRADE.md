# OpenCCVoice Guidance Controller  
# アップグレード注意点（〜v1.80i）
# 最終更新日: 2026-03-24

本書は、OpenCCVoice を **v1.80i** にアップグレードする際の  
重要な注意点・確認手順をまとめた技術者向けドキュメントです。  
特に **v1.73f1 / v1.80h 系** からの更新時にご確認ください。

--------------------------------------------------------------------

## 1. v1.80i の概要

v1.80i は v1.80h のコード整理版です。EEPROM CONFIG_VERSION は 5 のまま変更なし。
v1.80h からの書き込みは EEPROM 操作不要です。v1.73f1 以前からは自動マイグレーションが実行されます。

### v1.80h → v1.80i の変更点

| 項目 | 内容 |
|------|------|
| カーチャンク時の busySupUntil | 二重セットを修正。起点A（POST終了）に一本化 |
| ver=3 以前からのマイグレーション | pttPreMs / pttPostMs の不定値リスクを修正 |
| handleStoppedState() | 内部のデッドコード（Serial.read ブロック）を削除 |
| コメント | 旧用語・内部開発版番号を修正 |
| EEPROM CONFIG_VERSION | 5（変更なし） |

### v1.73f1 → v1.80i（v1.80h）の主な変更点

| 項目 | v1.73f1 | v1.80i |
|------|---------|--------|
| EEPROM CONFIG_VERSION | 4 | 5 |
| ② MAX（b）デフォルト | 3900ms | 1500ms |
| ⑤ 抑止時間（r）デフォルト | 3000ms | 10000ms |
| PRE 時間の制御 | 固定 1000ms（コマンド不可） | `j####` で可変（EEPROM保存） |
| POST 時間の制御 | 固定 1000ms（コマンド不可） | `J####` で可変（EEPROM保存） |
| 連打抑止（BURST） | あり | 廃止（⑤抑止に統合） |
| 送信直後ガード（postTxIgnore） | あり | 廃止（⑤抑止に統合） |
| `s0/s1` コマンド（抑止 ON/OFF） | あり | 廃止（常時有効） |
| `t0/t1` コマンド（送信後抑止 ON/OFF） | あり | 廃止（r0 で実質 OFF） |
| `i####` コマンド（送信直後ガード閾値） | あり | 廃止 |
| `H` コマンド（汎用プリセット） | あり | 廃止 |
| STOP 復帰コマンド | `r` | `R`（大文字） |
| ログレベルコマンド | `0/1/2/3` | `l0/l1/l2/l3` |
| 定周期ID 条件不成立時 | 延期（periodicDue 保持） | スキップ（破棄） |

## 2. EEPROM の扱い（v1.73f1 / v1.80h → v1.80i）

### ● v1.80h からのアップグレード

v1.80h → v1.80i は EEPROM CONFIG_VERSION が変わらないため、マイグレーションは実行されません。

```
[EEPROM] Settings Loaded.
[START] OpenCCVoice v1.80i
[LOG] MIN (l1=min l2=full l3=dbg l0=off)
```

### ● v1.73系（ver=4）からのアップグレード

v1.73系からスケッチを書き込むと、起動時に自動マイグレーションが実行されます。

| 処理 | 内容 |
|------|------|
| `pttPreMs` / `pttPostMs` を補完 | 1000ms で補完 |
| `busyMax` が旧デフォルト（3900ms）の場合のみ | 1500ms に更新 |
| `txSupMs` が旧デフォルト（3000ms）の場合のみ | 10000ms に更新 |
| `periodQuietMs` が 0 または異常値の場合 | 2000ms に補完 |
| `tmBusyActiveHigh` が不正値の場合 | 1（HIGH=busy）に補完 |
| `dfpTimeoutMs` が 600000 超の場合 | 20000ms に補完 |
| `pttPreMs` / `pttPostMs` が範囲外（100〜5000 外）の場合 | 1000ms に補正 |

> **注意**: `busyMax` と `txSupMs` のマイグレーション更新は「旧デフォルト値と一致する場合のみ」行われます。意図的に旧デフォルト以外の値（例：b2000、r5000）に設定していた場合は、その値がそのまま引き継がれます。

### ● 起動時の想定ログ

v1.73系（ver=4）からの更新時：
```
[EEPROM] Version mismatch: stored=4 expected=5
[EEPROM] Migration done.
[EEPROM] Settings Loaded.
[START] OpenCCVoice v1.80i
[LOG] MIN (l1=min l2=full l3=dbg l0=off)
```

初回起動またはデータ破損時：
```
[EEPROM] No/Other Data. Init defaults.
[EEPROM] Settings Loaded.
[START] OpenCCVoice v1.80i
[LOG] MIN (l1=min l2=full l3=dbg l0=off)
```

### ● 起動後に必ず実行すべき確認

`V` を入力してバージョンを確認：
```
[VER] OpenCCVoice v1.80i (EEPROM_VER=5)
```

`q` を入力して設定を確認：
```
[CFG] EEPROM_VER=5 SRC=D6 MIN=500 MAX=1500 PRE=1000 POST=1000 SUP=10000 PER(min)=30 QUIET(ms)=2000 A0[L/H]=300/700 HOLD=800 AUTO(min)=30 DFP_TO=20000 POL=HIGH=busy
```

チェックポイント：
- `EEPROM_VER=5`（正常）
- `MAX=1500`（マイグレーション後の新デフォルト、または意図した値）
- `SUP=10000`（マイグレーション後の新デフォルト、または意図した値）
- `PRE=1000` / `POST=1000`（補完値、または意図した値）
- BUSY 極性が無線機仕様に一致（g0/g1）
- 定周期間隔が意図した値

## 3. 「F（Factory Reset）」は必要か？

### ● 原則：不要

自動マイグレーションが正常に機能するため、通常は F 不要です。

### ● 以下の場合は F を推奨

- v1.69 系以前から一気に更新した
- 過去に手動で不正な値を設定した
- 今回を機に完全にクリーンな状態にしたい
- 起動ログに異常値補正が多数出た場合

実行手順：
```
F
q
```

## 4. v1.73系から変わった操作コマンドの一覧

### ● 廃止されたコマンド（v1.73f1 → v1.80h）

以下のコマンドは v1.80h で廃止されました。入力しても反応しません（unknown として無視されます）。

| 廃止コマンド | 旧機能 | v1.80h での代替 |
|------------|--------|---------------|
| `s0/s1` | 抑止全体 ON/OFF | 廃止（抑止は常時有効）。実質OFFは `r0` |
| `t0/t1` | 送信後抑止 ON/OFF | 廃止。`r0` で送信後抑止を実質無効化 |
| `i####` | 送信直後ガード閾値 | 廃止（⑤抑止に統合） |
| `H` | 汎用プリセット（s0/t0/b3900） | 廃止 |
| `r`（引数なし） | STOP 復帰 | `R`（大文字）に変更 |
| `0/1/2/3`（単体数字） | ログレベル | `l0/l1/l2/l3` に変更 |

### ● 変更されたコマンド

| コマンド | v1.73f1 | v1.80h |
|---------|---------|--------|
| STOP 復帰 | `r`（引数なし） | `R`（大文字） |
| ログレベル | `0/1/2/3` | `l0/l1/l2/l3` |

### ● 追加されたコマンド

| コマンド | 機能 | デフォルト |
|---------|------|-----------|
| `j####` | ③ PTT先行無音時間 PRE（ms） | 1000ms |
| `J####` | ④ PTT後行無音時間 POST（ms） | 1000ms |

## 5. 動作仕様の変更点と影響

### ● ② MAX（b）デフォルト変更（3900ms → 1500ms）

v1.73f1 では 3900ms がデフォルトでしたが、v1.80h では 1500ms に変更されました。

マイグレーション時：旧デフォルトの 3900ms で使用していた場合は 1500ms に自動更新されます。
意図的に 3900ms 以外（例：b5000）を設定していた場合はその値が保持されます。

**影響**：1500ms〜3900ms の受信が、旧仕様では「カーチャンク（ID送出）」でしたが、新仕様では「通常会話（⑤抑止）」として扱われます。運用環境によっては `b####` の再調整が必要です。

### ● 連打抑止（BURST）の廃止

v1.73f1 では「10秒窓内に短発2回以上で連打抑止10秒」という個別ロジックがありましたが、v1.80h では廃止されました。代わりに、カーチャンク検出のたびに ⑤ 抑止（r####）がリセット・延長される設計になっています。

**影響**：短時間に複数のカーチャンクが来た場合、旧来の連打抑止動作とは挙動が異なります。`r####` の値を適切に設定することで調整可能です。

### ● 送信直後ガード（postTxIgnore）の廃止

v1.73e/f1 では PTT OFF 直後に別個の `postTxIgnore` フラグで送信直後の誤発火を防止していましたが、v1.80h では廃止され ⑤ 抑止（busySupUntil）に統合されました。

**影響**：`i####`（送信直後ガード閾値）コマンドは廃止されます。送信直後の挙動は ⑤ 抑止時間（`r####`）で制御します。

### ● 定周期IDのスキップ仕様

v1.73系では定周期IDの到来時に条件不成立（受信中・抑止中・PTT中）の場合、`periodicDue` を保持して次の機会を待っていました（延期仕様）。

v1.80h では条件不成立の場合はその回をスキップ（破棄）します。次の定周期タイミングまで待機します。

**影響**：通話が頻繁な環境では定周期IDが送出されない場合が増えます。`k####` を短くするか `p##` の周期を見直してください。

## 6. アップグレード後のチェックリスト（v1.80i）

```
1. スケッチを書き込む
2. 起動ログを確認：
   - v1.73系からの更新: "Version mismatch: stored=4" → "Migration done." → "Settings Loaded."
   - 初回またはデータ破損: "No/Other Data. Init defaults." → "Settings Loaded."
3. V を実行し、"OpenCCVoice v1.80i (EEPROM_VER=5)" を確認
4. q を実行し、以下を確認：
   - EEPROM_VER=5
   - MAX=1500（または意図した値）
   - SUP=10000（または意図した値）
   - PRE=1000 / POST=1000（または意図した値）
   - POL が無線機と一致（g0/g1）
   - 定周期間隔 PER(min) が意図した値
5. BUSY 極性を実機で確認（g0/g1）
6. カーチャンクID（001）が正常に動作するか確認
7. 通常会話中（dur ≥ b####）に ID が出ないことを確認
8. ⑤ 抑止が正常に解除されることを確認（D13 消灯、または [SUP] CLEAR ログ）
9. 定周期IDが意図したタイミングで送出（またはスキップ）されることを確認
10. Z コマンドで再起動 → 設定が保持されていることを確認
11. 必要なら b#### / r#### / j#### / J#### / k#### を調整
12. 完全クリーン起動が必要なら F → Z
```

## 7. よくある質問（FAQ）

**Q1. v1.73f1 → v1.80i は特別な操作は必要？**  
→ 原則なし。スケッチ書き込みのみで自動マイグレーションが実行されます。

**Q1b. v1.80h → v1.80i は特別な操作は必要？**  
→ 不要。EEPROM CONFIG_VERSION が変わらないため、スケッチ書き込みのみで完了です。

**Q2. 旧設定は残る？**  
→ 基本的には残ります。ただし `busyMax` が旧デフォルト（3900ms）、`txSupMs` が旧デフォルト（3000ms）だった場合は自動的に新デフォルト値に更新されます。

**Q3. `s0/t0` を使って抑止を無効にしていたが、v1.80i では？**  
→ `s0/s1` / `t0/t1` コマンドは v1.80h で廃止されました。送信後抑止を実質無効にしたい場合は `r0` を使用してください。

**Q4. `i####`（送信直後ガード閾値）を設定していたが、v1.80i では？**  
→ `i####` コマンドは v1.80h で廃止されました。送信直後の挙動は ⑤ 抑止時間（`r####`）で制御します。

**Q5. STOP 復帰コマンドが `r` から `R` に変わったのはなぜ？**  
→ 旧来 `r` コマンドが「送信後無視時間の設定（r####）」と「STOP復帰（引数なし）」を兼用していたため、コマンド体系が分かりにくい問題がありました。`R`（大文字）に分離することで明確化しました。

**Q6. ログレベルコマンドが変わった**  
→ 旧 `0/1/2/3`（単体数字）から `l0/l1/l2/l3` に変更されました。起動時は常に l1=MIN（必要最低限のログ）です。EEPROM には保存されません。

**Q7. 定周期IDが全く送出されなくなった**  
→ スキップ仕様への変更により、受信中・抑止中が多い環境ではスキップが増えます。`k####` を短くするか（例：k500）、`p##` の周期を見直してください。`q` で `QUIET(ms)` と `PER(min)` を確認してください。

**Q8. 通常会話中に ID が出なくなった（旧 b3900 超えだった）**  
→ `b####` のデフォルトが 1500ms に変わったため、旧 3900ms デフォルト時とはカーチャンク判定範囲が変わっています。`b####` の値を `q` で確認し、必要に応じて再設定してください。

**Q9. BUSY判定が逆っぽい**  
→ `g0`（LOW=busy）/ `g1`（HIGH=busy）を確認してください。`q` で `POL=` を確認可能です。

**Q10. `F` → `Z` の完全クリーン起動後の確認方法は？**  
→ 起動ログに `No/Other Data. Init defaults.` が出て EEPROM_VER=5 になっていれば正常です。`q` で全設定がデフォルト値になっていることを確認してください。

## 8. まとめ

| バージョン | 主な追加・改善 |
|-----------|---------------|
| v1.73c | EEPROM 自動移行・安全補完 |
| v1.73d | 定周期ID 静寂ガード（k####） |
| v1.73e | 送信直後ガード・周期ID catch-up 対策（v1.80h で統合・廃止） |
| v1.73f | `V`（バージョン確認）・`Z`（ソフトウェアリセット）コマンド追加 |
| v1.73f1 | `v` → `V` コマンド変更（v2.x 系との競合回避） |
| **v1.80i** | **コード整理・マイグレーション修正・デッドコード削除** |

通常は F・Z ともに不要。スケッチ書き込み後に `V` でバージョンを、`q` で設定を確認してください。  
v1.80h からの書き込みは EEPROM の変化なし。v1.73系からの場合は特に `MAX=` と `SUP=` の値がマイグレーション後に意図した値になっているかを必ず確認してください。
