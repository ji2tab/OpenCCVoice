## DFPlayer Mini のファイル再生仕様

DFPlayer Mini は microSD カード上の音声ファイルを管理する小型モジュールです。
ファイル名の数字順に「トラック番号」が割り当てられ、Arduino からトラック番号を
指定して再生を命令します。

### ファイル命名規則

```
001.mp3   ← トラック1
002.mp3   ← トラック2
003.mp3   ← トラック3
```

- ファイル名は **3桁のゼロ埋め数字**（001〜999）で始めること。
- 拡張子は `.mp3` を推奨（`.wav` も可）。
- **ファイル名の数字順がそのままトラック番号になります。**
- microSD は FAT32 でフォーマット（推奨）。
- ルートディレクトリ直下に配置すること（サブフォルダ不可）。

---

## ⚠️ トラック順がずれる原因と対策

DFPlayer Mini のトラック番号割り当ては **ファイル名だけでは決まりません。**
以下の要因が複合的に影響することが報告されています。

### 原因1：SD カードへの書き込み順（最も多い原因）

FAT ファイルシステムはファイルをコピーした順番（書き込み順）でディレクトリエントリを
記録します。DFPlayer Mini はこのディレクトリエントリの並び順をトラック番号として
使用する場合があります。

**例：** `003.mp3` → `001.mp3` → `002.mp3` の順にコピーすると、
ファイル名とは無関係にコピー順でトラック1/2/3が割り当てられることがあります。

### 原因2：ファイルのタイムスタンプ

一部の DFPlayer Mini ファームウェアはタイムスタンプの古い順にトラックを割り当てる
という報告があります。PC の時計がずれている場合や、ファイルコピー時に
タイムスタンプが変わった場合に意図しない順序になることがあります。

### 原因3：ファームウェアの個体差

DFPlayer Mini にはいくつかのファームウェアバージョンが存在し、
トラック番号の割り当てルールが異なる場合があります。

## ✅ 確実なセットアップ手順（必ず守ること）

トラック順のトラブルを避けるため、以下の手順を**必ず守ってください。**

```
1. microSD カードを FAT32 で【完全フォーマット】する
   （クイックフォーマットではなく通常フォーマット）

2. 001.mp3 → 002.mp3 → 003.mp3 の【番号順に1ファイルずつ】コピーする
   （まとめてドラッグ＆ドロップしない）

3. コピー後はファイルの【追加・削除・名前変更をしない】
   （ディレクトリエントリの並びが変わるため）

4. タイムスタンプを揃えるため、コピー後にファイルのタイムスタンプを
   001 → 002 → 003 の順で古くなるよう設定するとより確実
   （Windows の場合:「TouchTimestamp」等のツールが利用可能）
```

> **もしトラック順がずれた場合は、SD カードを完全フォーマットして
> 上記手順でコピーし直してください。**

## OpenCCVoice v2.30 でのトラック割り当て

| トラック | ファイル名 | 用途 | 送出タイミング |
|---------|-----------|------|---------------|
| **1** | `001.mp3` | **カーチャンク ID** | 他局の電波（BUSY）検知後、送信が途切れた直後 |
| **2** | `002.mp3` | **定周期 ID（奇数回）** | 設定した周期（例: 30分）ごとに交互送出 |
| **3** | `003.mp3` | **定周期 ID（偶数回）** | 設定した周期ごとに 002 と交互送出 |

### なぜ定周期を 002/003 で交互にするのか

定周期 ID は同じ音声を繰り返すだけでなく、**2種類の音声を交互に送出することで
多様な案内（例：呼び出し方法とレピータ周波数）を届ける**ことができます。
002 と 003 に異なる内容を録音することで、1回の周期で2つの情報を伝えられます。
もちろん 002 と 003 を同じ内容にしても構いません。

---

## ✅ 必ず 001〜003 の3ファイルを用意すること

OpenCCVoice では **001・002・003 の3ファイルが必ず必要です。**
内容が1種類または2種類しかない場合でも、ファイル数は3つ用意してください。

### 内容が1種類しかない場合（コピー＆リネームで対応）

```
001.mp3  （オリジナル）
  ↓ コピー＆リネーム
002.mp3  （001 と同じ内容）
003.mp3  （001 と同じ内容）
```

### 内容が2種類の場合（コピー＆リネームで対応）

```
001.mp3  カーチャンク ID
002.mp3  定周期 ID
003.mp3  （002 をコピー＆リネーム、同じ内容）
```

> **ファイルが不足している場合の挙動は保証されません。**
> DFPlayer Mini の個体やファームウェアによって、直前のトラックを再生する・
> 無反応になる・誤ったトラックを再生するなどさまざまな動作が報告されています。
> **必ず3ファイルを揃えてください。**

## 推奨ファイル構成

2種類の異なる定周期メッセージを使う場合（フル活用）：

```
microSD/
  ├── 001.mp3   カーチャンク ID（例：コールサイン読み上げ）
  ├── 002.mp3   定周期 ID A（例：ネット接続の案内、アクセス方法の案内）
  └── 003.mp3   定周期 ID B（例：簡易音声案内、運用情報の案内）
```

定周期メッセージを1種類にする場合（最小構成）：

```
microSD/
  ├── 001.mp3   カーチャンク ID
  ├── 002.mp3   定周期 ID
  └── 003.mp3   002 をコピー＆リネーム（同じ内容）
```

## 音声ファイル制作のヒント

- フォーマット: MP3（128kbps 推奨）、サンプリング 44.1kHz または 32kHz
- 音量: DFPlayer の音量コマンドで 0〜30 の範囲で調整可能（起動時に 20 に設定）
- 無音部分: ファイルの先頭・末尾に 0.2〜0.5秒 程度の無音を入れると
  PTT 前後のノイズが軽減されます
- 録音内容例:
  - 001: コールサイン（短く明瞭に）
  - 002: ネット接続の案内、アクセス方法の案内など
  - 003: 簡易音声案内、運用情報の案内など
