    # 最終更新日: 2026-01-26

    ## 1. 重要：EEPROM のバージョン管理（version stamp）の導入

    **v1.73c から EEPROM にレイアウト版（`config.ver`）を導入**しました。  
    これにより、スケッチ更新後の **設定破損・不定値混入を自動で防止**します。

    ### ● 起動時の自動判定（version/magic チェック）
    起動時に以下を比較します：

    - `config.magic`（プロジェクト識別子）  
    - `config.ver`（EEPROMレイアウトの世代番号）

    不一致がある場合：

    - **自動マイグレーション**（旧レイアウトの値を新レイアウトへ自動補完）  
    - または **初期化（applyDefaults）** を実行  

    新規項目が EEPROM に存在しない場合（例：`tmBusyActiveHigh`、`dfpTimeoutMs` 等）も、  
    **既定値で自動補完**され、安全に動作します。

    > ▼ ポイント  
    > v1.73c 以降は、**スケッチ書き込み直後に “F” を実行する必要がありません**。  
    > ただし完全初期化してクリーンにしたい場合は F を推奨します。

    ## 2. v1.73b / v1.73c で追加された主な項目（旧EEPROMに未定義）

    ### ● 新規追加（自動補完対象）

    | 項目名               | 役割 | コマンド |
    |----------------------|------|----------|
    | `tmBusyActiveHigh`   | BUSY 極性（D6） | `g0/g1` |
    | `dfpTimeoutMs`       | DFPフェイルセーフ時間 | `d####` |
    | `ver`                | EEPROMレイアウト版 | 自動管理 |

    ### ● 旧EEPROMを読み込んだ場合の自動補完値（v1.73c の例）
    - `tmBusyActiveHigh = 1`（HIGH=BUSY）
    - `dfpTimeoutMs = 20000`（20秒）
    - `ver = 3` に更新

    これにより以下の不具合を防ぎます：

    - BUSY の極性逆転による誤動作  
    - PTT の張り付き  
    - DFPlayer タイムアウト誤動作  
    - AUTO 判定の誤り

    ## 3. 書き込み直後の正常な挙動

    ### ● 起動時に出る想定ログ

\[EEPROM] Version mismatch: stored=2 expected=3
\[EEPROM] Migration/completion done -> updated version.
\[EEPROM] Settings Loaded.
\[START] OpenCCVoice v1.73c Unified/Safe ...

```

### ● 起動後に必ず実行すべき確認
`q` を入力：

```

\[CFG] EEPROM\_VER=3 SRC=D6 ... TM\_BUSY\_POL=HIGH=busy DFP\_TIMEOUT(ms)=20000 ...

```

### ● チェックポイント
- `EEPROM_VER=3`（v1.73c に正常移行済み）  
- BUSY 極性が無線機仕様に一致（g0/g1）  
- d####（DFP_TIMEOUT）が意図した値  
- A0/D6/抑止/周期ID の設定値が残っていること

## 4. 「F（初期化）」は必要か？

### ● 原則：不要
v1.73c 以降では、自動移行が正常に行われるため、  
スケッチ書き込み直後に F を打つ必要はありません。

### ● ただし以下の場合は F を推奨
- 旧世代（v1.69以前）から一気に更新した  
- 過去に手動でおかしな値を設定した覚えがある  
- 今回を機にクリーンな状態でやり直したい  
- 起動ログに異常値補正が多数出た場合  

初期化は次の通り：
```

F
q

```

## 5. v1.73d への追加注意点（Periodic Quiet Guard）

v1.73d では、周期IDが「通話に割り込む」現象を抑えるための  
**静寂ガード**（Quiet Guard）が導入されました。

### ● 新規項目（v1.73d）
| フィールド名 | 役割 | コマンド | 既定値 |
|--------------|------|----------|---------|
| `periodQuietMs` | BUSY OFF→静寂してから送出するまでの時間 | `k####` | 2000ms |

### ● 周期ID（002/003）が送出される条件（v1.73d）
1. periodicDue=true  
2. state==IDLE  
3. readBusy()==false（受信していない）  
4. **BUSY が OFFになってから periodQuietMs 以上 静寂**  
5. 抑止中（長話/バースト/送信後）ではない  

→ 条件を満たさない場合は **延期（periodicDue を保持）**。

### ● v1.73c → v1.73d の自動移行内容
- 旧 EEPROM に `periodQuietMs` が無い場合：  
  → 自動で **2000ms** をセットして保存  
- `config.ver = 4` に更新  
- tmBusyActiveHigh / dfpTimeoutMs も引き続き安全補完

## 6. アップグレード後のチェックリスト（v1.73d含む）

```

1.  スケッチを書き込む
2.  起動ログに Migration / Loaded が出ることを確認
3.  q を実行し、
    *   EEPROM\_VER=4（v1.73d）
    *   TM\_BUSY\_POL（g0/g1）が無線機と一致
    *   DFP\_TIMEOUT(ms)=20000
    *   QUIET(ms)=2000（または設定値）
4.  BUSY の極性を実機で確認（反応の有無）
5.  短発ID（001）が正常に動くか確認
6.  周期IDが「通話中に割り込まない」ことを確認
7.  必要なら k#### を調整（例：k5000）
8.  必要なら F でクリーン初期化 → 再設定

```

## 7. よくある質問（FAQ）

### Q1. v1.73c / v1.73d に更新したら何か特別な手順は必要？
→ 原則 **なし**。自動移行が働きます。

### Q2. 旧設定は残る？
→ **残ります。** 新しい項目だけ安全値で補完。

### Q3. 周期IDがまだ割り込む気がする？
→ `k####` が短い可能性。  
　`k3000〜k5000` などへ調整して下さい。

### Q4. BUSY判定が逆っぽい？
→ `g0（LOW=busy）` / `g1（HIGH=busy）` を確認。  
　`q` で常に現在の極性を確認可能。

## 8. まとめ

- v1.73c は **EEPROM 自動移行**が入り、更新時の安全性が大幅向上。  
- v1.73d は **周期IDに静寂ガードを導入**し、通話割り込み問題をほぼ解消。  
- 旧設定は保持され、新項目のみ安全値で補完される。  
- 通常は “F” は不要、必要な場合だけ実行でよい。

OpenCCVoice の長期安定運用のため、  
v1.73d への更新を推奨いたします。
```
